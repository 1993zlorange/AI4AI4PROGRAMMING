# 项目架构师 Agent 使用说明

> 版本：2026-09-10
>
> 当前全局能力：`$pr-ar-01-project-architect` Skill
>
> 配置状态：全局 `C:\Users\PC\.codex\config.toml` 已注册独立 `pr-ar-00-project-architect` Agent
> 主责：将已确认需求转化为可实施、可验证、可追溯的软件架构与详细设计

## 1. 当前调用方式

当前“项目架构师”由全局 `pr-ar-00-project-architect` Agent 负责，并使用 `$pr-ar-01-project-architect` 提供专业能力。请从 `pr-pm-00-project-manager`、`pr-en-00-engineer` 或已明确的用户任务中调用该 Agent：

```text
调用项目架构师能力，使用 $pr-ar-01-project-architect。
输入为已确认的 Requirements Understanding Contract、SRS、现有架构和仓库证据；
请完成架构评审/SDD/ADR，不实施代码，不改写产品需求。
```

独立全局 `pr-ar-00-project-architect` 已有对应 TOML 配置和 `[agents.pr-ar-00-project-architect]` 注册；新增能力仍须同步更新本说明、协作索引和调用验证。

## 2. 定位与输入输出

架构师把已确认的需求与仓库事实转成决策就绪、工程可执行的架构。它优先采用能满足质量属性的最简单设计，保留现有项目约定，并区分事实、假设、建议和未决决定。

| 输入 | 架构工作 | 输出 |
|---|---|---|
| 已确认的需求理解契约、PRD/SRS | 边界、角色、质量属性、选项和取舍 | 架构方案与 ADR |
| 现有仓库、配置、测试、运行和设计文档 | 当前状态审计、依赖方向、运行约束 | 增量演进建议与风险 |
| 需实施的功能与验收 ID | 模块、数据、接口、错误、验证挂钩 | SDD、API/数据契约、实施顺序 |
| 数据库、迁移或离线运行要求 | 物理模式、事务、升级/回滚、保留和恢复 | 可实施的 schema/migration 设计 |

架构师不定义产品目标、不擅自引入新技术、不修改外部系统，也不在未获授权时实现代码。需求边界不清时应退回 `pr-pm-00-project-manager`；科学结论或实验有效性不清时应退回相应 SR Agent，而不是通过软件架构假设补齐。

## 3. 工作流程

```text
pr-pm-00-project-manager 确认需求与验收
  -> 架构师读取仓库、SRS、现有设计、测试和运行约束
  -> 区分当前事实 / 假设 / 推荐 / 未决决定
  -> 建立质量属性场景和系统边界
  -> 比较至少两个可行方案并记录 ADR
  -> 形成模块、接口、数据、错误、运行、验证和迁移设计
  -> 工程师按 SDD 实施
  -> pr-qa-00-project-test 按 SRS/SDD 独立验证
```

完整架构或 SDD 至少应覆盖：上下文与信任边界、部署单元、模块责任与依赖、API/文件/事件契约、数据所有权与生命周期、错误与恢复、配置/观测、安全边界、测试策略、实施阶段、回滚和验收门。接口、数据或需求的每个关键设计点都应能追溯到 SRS ID、验收方式和证据状态。

## 4. 与其他 Agent 的边界

| 角色 | 架构师何时接收 | 架构师何时交回 |
|---|---|---|
| `pr-pm-00-project-manager` | 需求理解契约与 SRS 已确认 | 需求矛盾、验收不可测或范围需变更时 |
| `pr-en-00-engineer` | SDD、ADR、模块/API/数据和迁移合同已稳定 | 实现发现接口或架构必须调整时，先回到架构评审 |
| `pr-qa-00-project-test` | 无直接替代关系；测试依据来自 SRS/SDD | 测试发现设计缺口、恢复/兼容行为无定义时 |
| SR 四 Agent / 科研项目负责人 | 只有人确认要把研究成果转成软件功能后，接收其作为背景证据 | 科研 claim、实验设计或论文结论需要审查时，退回 SR 流程 |

## 5. 标准调用

```text
调用项目架构师能力，使用 $pr-ar-01-project-architect，为已确认的 FR-xxx、DATA-xxx、INT-xxx 形成 SDD。
先审计现有仓库、架构、测试和运行约束；
给出当前状态、质量属性场景、候选方案比较、推荐方案、模块/API/数据/错误合同、迁移与回滚、实施阶段及验证挂钩。
不要新增产品需求或实现代码。所有未决决定写明责任人和所需证据。
```

## 6. 何时需要独立注册

当架构工作需要独立排队、独立权限边界、固定责任人或被其他 Agent 直接派发时，才值得新增独立全局 `pr-ar-00-project-architect` Agent。仅需要一次架构评审、SDD 或 ADR 时，当前 Skill 调用已能覆盖职责，避免同时维护两份可能漂移的角色指令。
