## 2. 现有 Skill 覆盖缺口

现有全局能力分别覆盖项目监理、前端设计、文档写作和浏览器验证，但没有一个项目级 Skill 同时约束：

- Markdown 事实源与 HTML 呈现层的关系；
- 项目监理登记、路径归属和治理闭环；
- 多文档信息架构和排除范围；
- 每份文档的逻辑图；
- 离线单文件和外部依赖禁止；
- 项目 F001 与 Playwright 多视口验证；
- 截图、Console、PageError、横向滚动和治理记录落点。

因此需要一个归项目监理使用的项目级候选 Skill，而不是继续把规则散落在单次日志中。

## 3. 职责、触发、非目标、输入与输出

**唯一职责**：把已登记、已存在的 Markdown 项目文档转换为可审阅的离线 HTML 门户，并保证呈现范围、逻辑图、来源追溯和验证证据可审计。

**触发**：

- 用户要求将需求、设计、流程、治理或交付文档转为 HTML；
- 用户要求整合多个 Markdown 文档为文档门户；
- 用户要求补充导航、页内大纲、搜索、主题或逻辑图；
- 已有 HTML 门户需按批准范围更新。

**非目标**：

- 不修改 Markdown 事实源；
- 不实现产品后端或业务功能；
- 不部署、上传、提交或发布；
- 不复制第三方品牌；
- 不替代独立测试或用户验收。

**输入**：项目 `AGENTS.md`、源 Markdown 清单、当前批准流程、包含/排除范围、目标读者、输出落点、格式参考、验证命令。

**输出**：日期化 HTML、逐文档逻辑图、浏览器证据、治理记录和残余风险说明。

## 4. 失败边界、权限、幂等与并发

- 源文档、输出目录或呈现范围不清时阻塞；
- 目标文件已存在且归属不明时不得覆盖；
- 不读取凭据、不写入外部系统、不引入运行时 CDN；
- HTML 不承载秘密、生产数据、机器绝对路径或真实日志；
- 重复执行必须保留最新批准范围，不恢复用户明确排除的内容；
- 同一 HTML 文件同一时间只能有一个写入责任人；
- 临时脚本和 `.playwright-cli` 产物结束后清理；
- 本地 HTTP 服务和浏览器会话结束前关闭。

## 6. 试点、指标、验证、回滚和人工决定

- **生命周期**：候选 → 项目试点 → 独立评审 → 人工批准 → 启用 → 监控 → 优化/合并/淘汰。
- **试点范围**：下一个项目监理负责的 Markdown 文档 HTML 呈现任务。
- **指标**：源文档覆盖完整、用户排除项不再出现、每页逻辑图准确、F001 通过、Console/PageError 为 0、多视口无横向滚动、返工减少。
- **验证**：结构检查、静态扫描、F001、Playwright 1440/900/390/320、导航、搜索、主题、复制、页内大纲和截图证据。
- **回滚**：删除或替换本次 HTML 呈现层；治理记录保留审计事实。
- **人工决定**：用户已授权创建项目级候选 Skill；默认启用和全局晋升仍需后续人工批准。
