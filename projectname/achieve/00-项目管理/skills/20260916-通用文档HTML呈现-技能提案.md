# ps-10-document-html-presentation 通用文档HTML呈现技能提案

## 1. 演进证据

本项目已经完成多轮可复用实践：

1. 将 `20260915-软件项目Agent协作-流程说明.md` 与多份参考文档整合为离线 HTML 门户；
2. 按用户反馈调整呈现范围、移除干扰入口，并为每个保留文档补充逻辑图；
3. 参照 AI4SCIENCE 教学手册生成通俗易懂的项目手册，并完成浅/深主题、响应式、Console 和多视口验证；
4. 已形成项目级候选 Skill `ps-10-document-html-presentation` v0.1.0，归属项目监理。

用户随后明确要求：“总结成通用的文档到html的skill，赋予项目监理”。

## 2. 覆盖缺口

v0.1.0 已经覆盖 Markdown 项目文档到 HTML 的主要治理要求，但输入边界仍偏窄，未明确：

- 纯文本和既有 HTML 的处理；
- DOCX/PDF 等文档先经批准工具提取再转换的链路；
- 表格、演示文稿、扫描件和 OCR 的审计要求；
- 不同源类型的 sanitize、来源映射和不确定项标注；
- 非流程类文档的逻辑图/结构图选择。

因此演进现有 Skill，而不是创建重复 Skill。

## 3. v0.2.0 职责

**唯一职责**：项目监理把已登记、可读取、可追踪的文档源转换为离线 HTML 呈现层，并保证范围、提取链路、逻辑图、来源追溯和验证证据可审计。

**支持输入**：

- Markdown / 纯文本；
- 既有 HTML；
- 经批准文档工具提取的 DOCX/Word 文本；
- 经批准 PDF 工具提取的文本和表格；
- 登记过范围的表格、演示文稿和 OCR 文本。

**继续排除**：

- 不可读、无授权或无审计提取路径的二进制源；
- 产品业务代码生成；
- 自动部署、上传、提交或推送；
- 第三方品牌或受保护内容复制；
- 未确认的 OCR 结果直接写成事实。

## 4. 安全与质量边界

- 源文档和批准提取记录是事实源，HTML 是呈现层；
- 所有源文本转义后再入 HTML；
- 既有 HTML 必须清理脚本、事件属性、`javascript:` URL、未知 iframe 和不可信样式；
- 外部链接使用 `noopener noreferrer`；
- OCR/低置信提取内容标注不确定性，必要处等待人工复核；
- 默认单文件离线输出，不引入运行时 CDN；
- 每份保留文档有逻辑图或结构图；
- 执行静态扫描、F001、真实浏览器、Console/PageError 和 1440/900/390/320 响应式检查；
- 浏览器与提取证据放隔离 run-id 目录。

主模板：

- `projectname/project/.codex/skills/ps-10-document-html-presentation/assets/20260916-项目监理文档HTML呈现-输出模板.html`

规划模板：

- `projectname/project/.codex/skills/ps-10-document-html-presentation/assets/20260916-项目监理文档HTML呈现-输出模板.md`

模板保留既有稳定路径，内容已泛化为通用文档 HTML 输出结构，避免创建重复模板。

## 6. 试点与生命周期

- **生命周期**：候选 → 项目试点 → 独立评审 → 人工批准 → 启用 → 监控 → 优化/合并/淘汰。
- **试点范围**：下一个由项目监理负责的非纯 Markdown 文档转 HTML 任务，优先选择一份 DOCX 或 PDF 提取文档。
- **指标**：源覆盖完整、提取映射可追溯、逻辑图准确、无安全命中、F001 通过、Console/PageError 为 0、多视口无横向滚动、用户返工减少。
- **回滚**：将 Skill 恢复到 v0.1.0；已生成 HTML 删除或替换；治理记录保留。
- **人工决定**：用户已授权项目级候选 Skill 演进；默认启用和全局晋升仍需后续人工批准。
