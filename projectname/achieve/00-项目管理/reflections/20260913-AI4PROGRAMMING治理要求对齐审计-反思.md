# AI4PROGRAMMING 治理要求对齐审计反思

## 1. 目标与事实

- 关联需求/问题 ID：REQ-GA-01 至 REQ-GA-09；DRIFT-001 至 DRIFT-007。
- 预期结果：八项治理要求在通用软件模板中既有规则，又有可验证执行链。
- 实际结果：规则基本齐全，但通用 Agent、功能/目录自动校验、模板联动、日志防漏和 Skill 晋升仍缺少运行闭环。
- 证据：对齐审计偏差清单、全局 Agent 配置、空功能注册表、源码/测试扫描和 Skill 资产清单。

## 2. 偏差与根因

| 偏差 | 根因类别 | 已证事实 | 推测 | 影响 |
|---|---|---|---|---|
| 通用流程调用科研专用 Agent | 规则/实现 | 三个实际 Agent 配置明确写 `scienceresearch` 和固定专用流程 | 历史单项目配置未在模板通用化时同步拆分 | 新项目可能写错路径、调用错 Skill、生成错交付物 |
| 功能、目录和 Skill 晋升只有规则没有项目校验器 | 流程/实现 | 注册表为空，项目脚本目录只有占位文件，无晋升实例 | 模板建设先完成文档层，自动门尚未迁移 | 漏登记和越界只能靠人工发现 |
| 文档模板和日志闭环无法全量对账 | 规则/流程 | 主要 Skill 有模板和本批日志有影响字段，但无全量清单、请求计数和漏记检查 | `AGENTS.md` 被当作足够的运行拦截器 | 长任务、多 Agent 或失败路径更容易漏记录 |

## 3. 可复用规律

- 适用范围：所有从通用模板派生的软件项目，尤其是多 Agent、跨目录和发布任务。
- 不适用范围：不据此判断任何具体业务功能、性能、安全或正式验收结果。
- 同类历史证据：AI4SCIENCE 已使用功能/晋升只读校验器，说明自动门可作为小范围迁移候选，但不能复制科研路径和假设。
- 与现有规则的关系：不推翻现有规则，而是补足“规则 -> 执行 -> 验证 -> 演化”的缺环。

## 4. 最小改进与再验证

| 改进对象 | 责任人 | 路径 | 权限 | 验证 | 回滚 |
|---|---|---|---|---|---|
| 通用软件 Agent 与科研专用 Agent 解耦 | 全局 Agent 维护人 | 全局 Agent 配置 | 用户明确批准 | 固定项目名/路径扫描 + 临时项目派发测试 | 保留现有科研 Agent，新增或恢复其专用入口 |
| 提议 F001/F002 项目只读门 | 项目监理 + 工程师 | `project/scripts/` 与 `achieve/00-项目管理/tools/` | 另行实施授权 | 正常/失败/越界/重复/误触发测试和 API 说明 | 删除候选工具并恢复调用规则，不影响项目数据 |
| 建立文档模板清单和 preflight/postflight 对账 | 项目监理 + Skill 维护人 | 项目配置、Skill `assets/` 和治理记录 | 全局变更需人工审批 | 缺模板、漏需求、漏日志、未触发反思时非零退出 | 保留人工流程，关闭有误报的自动门 |

- 是否提议 Skill/规范演化：是，进入候选评估，不自动修改或安装。
- 人工决定：等待用户决定是否批准三个改进方向及其实施顺序。
